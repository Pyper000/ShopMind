## 1. 信息架构

任务输入 → 清单核对 → 商品匹配 → 效果反馈。账号与授权记忆是可选支线；候选审核是独立管理支线。

| 页面/区域 | 用户操作 | 预期系统结果 | 当前状态 |
| --- | --- | --- | --- |
| 任务输入 | 输入目标、地点日期、同行人与活动 | 可直接出清单；关键未知最多优先追问2项 | 已有模板/模型路径 |
| 清单 | 标已有/准备/未知/不需要 | 立即可见，确认后提交结构化状态 | 已实现 |
| 旅行细分 | 本人+儿童衣物、件数、天气/活动条件 | 与原行程约束一致，追问不丢天数 | 完整目标设计待验收 |
| 匹配 | 只提交确认缺项 | 可购缺项出同类候选，证件进入携带/办理 | 已有实现与测试 |
| 候选 | 每个槽位选择一个商品 | 按选中目录价计算预算，缺供给诚实提示 | 模拟目录已实现 |
| 反馈 | 点击有帮助/不准，之后更新买到/未找到等 | 同会话更新，不重复增加样本 | 已实现 |
| 游客/账号 | 刷新、开始新对话、可选登录 | 刷新恢复本机对话，新对话新session | 已实现，非跨设备同步 |
| 长期记忆 | 明确授权/撤回/清除 | 默认关闭，只对授权账号读写 | 已实现 |
| 模板候选 | 主动同意提交匿名模块 | 等待评测与人工审核，不直接发布 | 已实现本地流程 |

## 2. 旅行清单目标线框

```text
任务：东京3日，1成人+5岁儿童，计划游泳
天气：预报10–18℃ / 1个雨天（原型示例，并非实时查询）
[证件与设备] [本人衣物] [5岁儿童衣物]
[天气与活动] [洗漱及其他准备]
每项：具体名称 + 件数/套数 + 适用条件 + 四种状态
底部：预算/偏好 → 确认清单 → 只对可购缺项匹配
```

已有数据结构以item.name表示对象差异，尚未建立独立owner字段。原型中的对象模块是信息组织目标，不宣称后台已有完整家庭成员模型。

## 3. 关键规则与异常

- 护照点击“需要准备”：显示携带/办理，不推荐护照商品；不表示已完成办理。
- 本人和儿童衣物不得合并成一个泛化“衣物”；数量说明是估算，可按洗衣、体感和活动调整。
- 未提供日期：不显示确定温度或雨雪事实；有天数时仍可给基础数量估算。
- 下水用品须标计划下水条件；下雨、下雪对应不同装备。缺活动信息时保留按需。
- 模板更换与补充条件应区分；明确换目的地/日期时重取对应天气。
- 重试保留当前可用清单；等待/失败、目录无匹配、未授权、候选评测未通过应有明确结果。
- 支持键盘操作和窄屏；状态不能只靠颜色表达。
