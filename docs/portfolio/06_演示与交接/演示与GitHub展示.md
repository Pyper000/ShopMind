## 2. 三分钟讲述脚本

0:00–0:40 背景：欧洲旅行准备经历与研究反例，说明目标是陌生多品类任务，需求还需验证。
0:40–1:30 方案：打开[原型](../02_需求与原型/prototype.html)，本人/儿童、天数、天气/活动条件，演示证件准备与商品缺口分流。先说明旅行完整细分是目标设计。
1:30–2:10 实现：打开架构，解释MainAgent统一状态、SearchAgent按缺口、确定性约束与模板快路。
2:10–2:40 证据：打开本轮测试产物与历史猫场景截图/SSE，说明记录范围、模拟目录和自报结果。
2:40–3:00 复盘：展示高UV错误和旅行多轮缺口，以及下一轮用户对照测试。

讲述职责以个人项目和可核查产物为准，不虚构正式团队协作与线上业务指标。

## 3. 实际产品演示清单

入口：[本机5190](http://127.0.0.1:5190/)。面试前复核health与JSON接口。已有8013/5185服务不属于本轮切换对象。

1. 点“新对话”，输入“我第一次养一只健康成年猫”：核对模板与多模块。
2. 将食盆标已有、猫粮标需要准备，再确认：只猫粮进入候选；指出目录是模拟。
3. 点清单有帮助与还没买：说明这是测试反馈，会更新同会话记录，不是用户效果。
4. 刷新：说明本机游客恢复；点新对话创建另一任务；登录和长期记忆需分别操作。
5. 用狗输入验证不套猫模板；开放模型请求可能较慢，预备历史原始SSE。
6. 旅行复杂追问目前用于展示待修问题或目标设计；修复并重新验收前不作为稳定成功演示。

候选发布/回退会改变模板库，现场以独立隔离数据或原型展示。历史闭环记录已证明机制，本轮文档整理没有再执行发布操作。
