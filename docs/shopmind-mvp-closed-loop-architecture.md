# ShopMind MVP 闭环架构与阶段边界

## 核心约束

常用模板与新场景共用 `ShoppingPlan` / `checklist_sections` 输出结构；模板是经过验证的初始方案，不是另一套交互。清单项目的任务属性（必备/按需）与用户状态（已有/需要购买/还没确认/不需要）分开保存。

## 一轮任务的数据流

```text
用户 Query
  -> MainAgent / Orchestrator 识别场景并维护唯一方案状态
     -> 高置信且对象兼容：实例化版本化场景模板
     -> 无模板或低置信：生成 2–6 个模块的结构化新场景清单
  -> 用户逐项确认并确认预算、偏好
  -> MainAgent 只把明确需要购买的槽位提交给 SearchAgent
  -> SearchAgent 返回候选商品、目录事实与取舍信息
  -> MainAgent 组织 SSE 展示与方案确认
  -> 仅在用户明确进入购买，且交易能力真实接入后调用 TradeAgent
  -> 交易状态作为事实返回 MainAgent；无真实订单时只记录用户主动确认的结果
```

SSE 是向前端传递方案和候选事实的展示通道，不表示 SearchAgent 是会话或用户画像的所有者。用户在清单中点击状态，应作为结构化输入回到 Orchestrator；SearchAgent 不得根据检索行为推断“家里已有”。

## 职责边界

- **MainAgent / Orchestrator**：会话内方案状态的唯一协调者；应用用户明确给出的清单修改、预算和偏好，决定是否重新检索，并把结构化事件交给对应服务。它可以产出“模板候选”事件，但不直接发布模板。
- **SearchAgent**：只负责商品召回、过滤、排序和候选解释；输入是已经确认的待购槽位及检索约束，输出商品目录事实。它不写个人库存、用户偏好或模板库。
- **TradeAgent**：仅在真实交易链路接入后处理用户确认的购买/订单；只有订单系统事件或用户明确反馈能证明购买结果。MVP 无真实交易时不模拟成交。
- **个人记忆服务**：游客按本机会话保存；可选本地账号采用 PBKDF2 密码哈希和 30 天不透明 Bearer token。库存/偏好默认关闭，只有账号明确授权后才跨会话读写；撤回授权会立即停止读取，用户也可一键清除库存、偏好并撤回授权。清单状态与长期库存分开。
- **模板候选与审核流程**：只有用户主动点击同意后才提交匿名结构化模块；候选不接收原始 query、账号或会话 ID，并拒绝常见联系方式和地址格式。候选先通过结构评测，再由本机审核人补齐名称、用途和匹配词并显式发布版本；支持版本回退，单次模型输出不会自动进入模板库。
- **反馈与评测**：逐项修改回到 MainAgent 更新当前方案；清单有用/不够准确与“买到/未找到/决定不买/尚未购买”分别一键记录，并可按会话更新。聚合接口输出清单帮助率和用户自报购买结果，不把反馈伪装成订单事实。

## 场景路由与清单契约（MVP 第一阶段）

1. 词法命中或语义命中模板前，先检查对象/场景硬约束；明显冲突（例如狗 query 对养猫模板）必须拒绝匹配并回退开放场景，不以向量分数覆盖冲突。
2. 模板方案必须携带模板 ID 与版本，并生成模块、必备/按需项目；新场景模板 ID 为空，但必须用相同的 `checklist_sections` 结构，模块按场景目标组织。
3. 每个清单项目是可单独核对的具体物品，可带数量、条件或说明。按需表示“条件满足时再准备”，不是用户购买状态。
4. 清单状态缺省为待确认；模型不得推断用户已有或要买。只有用户明确确认的待购项进入商品检索。
5. 开放场景优先由模型提供 2–6 个有意义模块；工具层负责规范化、去重及顶层任务/按需集合与模块项目的一致性。确定性回退只能按已知物品用途分组，不能伪称它具备语义理解。

## MVP 阶段

1. 场景模板对象冲突防护、模板/新场景统一结构化清单。
2. 已知模板、语义改写、对象冲突和开放新场景回归评测。
3. 清单有用度一键反馈与“完成后是否买到”的显式记录和汇总。
4. 游客会话保存、可选登录，以及用户授权的个人库存/偏好记忆。
5. 匿名模板候选池、人工审核、版本发布和回退。

## 当前验收状态

- 阶段 1–5 的实现与自动化功能验收已完成；模板路由、结构化输出、评测、反馈、授权记忆、候选审核发布和版本回退均有回归测试。
- 真实交易接口尚未接入，因此“是否买到”仅是用户自报结果，不调用 TradeAgent、不创建订单。
- 清单效果指标已具备记录与汇总能力。自动化测试数据只能证明端到端记录逻辑工作；清单在真实用户中的帮助率需要累积实际反馈后才能判断，当前不能声称已经被真实用户验证。
- 本地账号仅服务当前本地 MVP，不接外部身份提供方；部署到公网前需单独设计密钥、会话保护、速率限制和审核员身份认证。
