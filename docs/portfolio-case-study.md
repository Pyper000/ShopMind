# Ecommerce 跨境购物搜索与决策 Agent

> 个人作品集｜模拟商品与模拟账户上下文｜不接真实支付、订单、物流或企业搜索日志

## 30 秒看懂

跨境购物用户常把品类、属性、预算、目的国和购买动作放在一句自然语言里。普通关键词搜索可能返回商品，却无法说明商品能否送达、是否超预算，或为什么没有结果。

我将这个问题设计成一条可解释链路：

`自然语言 Query -> 意图与槽位理解 -> 多路召回 -> 硬约束过滤 -> 推荐/无结果解释 -> 确认式行动`

项目价值不在于“做了一个聊天框”，而在于把搜索、推荐理由和后续购买动作连接起来，并用可复跑的离线评测检查效果与幻觉风险。

## 我解决了什么

### 1. 模糊需求如何进入搜索链路

将 Query 解析为品类、属性、预算、收货地和长期偏好。预算与目的国属于硬约束，不交给大模型自行判断；信息不足时先追问关键条件。

### 2. 为什么搜不到

将无结果区分为四类：商品库无供给、超预算、目的国不可达、信息不足。系统返回被过滤候选和原因，让用户知道应放宽哪个条件，而不是笼统回复“没有找到”。

### 3. 如何防止模型编造商品和价格

商品、库存、到手价和订单状态均来自工具返回；大模型负责意图表达与解释。交易写操作必须先展示确认信息，用户明确确认后才执行模拟操作。

## Agent 分工

| 角色 | 负责什么 | 解决的产品痛点 |
| --- | --- | --- |
| MainAgent | 判断找商品、咨询、比较或确认阶段；维护上下文；必要时派发子任务 | 多轮任务容易丢条件，简单任务又不应层层转交 |
| SearchAgent | Query 槽位解析、商品召回、硬约束过滤、结果解释与无结果归因 | 搜索结果相关但不可买，或零结果原因不透明 |
| TradeAgent | 确认卡、模拟下单、查单与取消 | 模型不能未经确认直接执行写操作 |

## 搜索能力

- 召回：向量召回与关键词/中文 2-gram 兜底。
- 排序：可接 HTTP reranker；不可用时显式降级为向量排序。
- 过滤：`category` 表示品类，`ship_to` 表示收货国家/区域，`price_max_major` 表示用户币种下的最高预算。
- 个性化：只使用用户主动表达并允许记录的长期偏好；当前没有真实行为日志、协同过滤或生产级双塔个性化召回。
- 知识问答：品类选购建议通过脱敏 Markdown 知识库检索，不与商品召回混为同一环节。

## 我的个人贡献

- 选择跨境购物作为场景，定义目标用户、关键任务和“搜得到但买不了”的问题。
- 拆解 Query 理解、召回、过滤、排序、解释与确认链路，明确规则和大模型的职责边界。
- 设计三 Agent 分工、无结果分类和交易确认机制。
- 扩充模拟商品目录并构建商品级、场景级评测集，整理结果与已知边界。
- 借助 AI 编程工具完成 Demo 实现与调试；我能重点讲解产品决策、搜索逻辑、数据口径和评测方法，不将其表述为独立手写生产级全栈系统。

## 演示顺序

1. 输入“300 元以内、抗造耐摔的露营灯”，观察预算槽位、召回策略和商品卡。
2. 输入“坐飞机脖子难受，有什么办法”，观察无“颈枕”字面的语义召回。
3. 输入“500 元以内、寄到欧洲的户外装备”，观察价格与目的国硬约束。
4. 输入商品库不存在的“4K 无人机”，观察不编造与替代建议。
5. 发起模拟购买，观察确认卡和明确确认后才能创建订单。
