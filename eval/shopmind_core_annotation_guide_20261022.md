# ShopMind 核心检索样本标注说明 v0.1

## 本轮范围

- 场景：周末海边、首次租房。
- 检索单元：一个场景下的一个明确采购槽位，对应一种用户 Query 表达。
- 样本：14 条 Query，7 个槽位；字面表达和语义表达各 7 条。
- 标注对象：当前模拟商品目录中的 `product_id`，以 `title`、`category`、`description`、`highlights` 为判断证据。
- 数据文件：`eval/shopmind_core_recall_20261022.jsonl`。

这是一份待人工复核的首版参考集，不是双人一致的正式 Gold Set。样本覆盖和正例由目录核对辅助整理，相关性边界、未标注候选及标注者一致性都需要人工复核。当前报告仅用于发现方向和建立基线，不用于对外声称模型准确率或业务提升。

## 标注口径

一个商品只有同时满足以下条件才标为相关：

1. 商品能直接完成当前 `shopping_task`，不能只因场景相似或大类相同就判相关。
2. 商品标题、类目或明确属性与 Query 中的关键需求一致；Query 有明确规格、用途或安装限制时，商品不能与之冲突。
3. 目录没有足够事实证明关键属性时，不猜测；标为待确认，不放入正例集合。

例如，“可夹在床边的小灯”不能仅凭“都是灯”纳入夜灯；“收纳箱”与“收纳筐”按不同任务槽位处理。现有 JSONL 记录 `relevant` 正例集合，未在列表中的 ID 暂按不相关计算，因此必须复核当前 Top-K 候选，避免漏标正例虚增 Precision。

## 字段

- `scene`：固定任务场景。
- `slot`：稳定的任务槽位 ID。
- `shopping_task`：送入检索链路的明确商品任务，也是硬过滤条件。
- `query`：用户可能使用的原始表达。
- `kind`：`lexical` 为字面词匹配，`semantic` 为不依赖商品名的需求表达。
- `relevant`：符合上述口径的商品 ID 集合；当前不编码可解释的等级排序。
- `note`：正例边界或容易混淆的近邻说明。

正式复核时应另记每位标注者对每个候选的 `relevant / irrelevant / uncertain`、理由和复核状态。分歧先讨论规则；无法一致时由第三人裁决，并把新边界补进本说明。首轮可先双人独立复核这 14 个 Query 对应的候选，再逐步扩至每个 Query 的 Top-K 结果。

## 指标与实验

- `Recall@8`：按 Query 宏平均，Top 8 返回结果中命中的相关 ID 数 / 该 Query 全部相关 ID 数。
- `Precision@8`：按 Query 宏平均，Top 8 实际返回候选中的相关 ID 数 / 实际返回候选数；空结果计 0。这是候选相关准确率，不是分类任务 Accuracy。
- `MRR`：每条 Query 第一条相关结果排名倒数的宏平均。
- 槽位过滤实验：对同一查询、同一关键词召回，配对比较关闭与启用 `shopping_task` 硬过滤的输出；除过滤外保持配置不变。
- 样本很小，当前只报描述性结果；门禁阈值不代表统计显著性。不能据此推断用户满意度、线上转化或 ROI。

当前 `relevant` 不含逐候选分级，`NDCG` 不作为本轮结论或简历指标。确认相关性边界后再补等级标注。

## 首轮结果与下一步

2026-10-22，关键词 `keyword_2gram` 档、K=8，14 条 Query：

| 配置 | Recall@8 | Precision@8 | MRR |
| --- | ---: | ---: | ---: |
| 关闭槽位硬过滤 | 0.629 | 0.339 | 0.643 |
| 启用槽位硬过滤 | 0.743 | 0.857 | 0.857 |

样本内候选 Precision +51.8 个百分点，Recall@8 +11.4 个百分点。按 Query 类型拆分，语义 Query 的 Recall@8 从 0.257 到 0.514，Precision@8 从 0.161 到 0.714；字面 Query 的 Recall@8 从 1.000 到 0.971。该变化反映槽位过滤压低跨品类噪声、也暴露同义词造成的漏召回，不表示真实线上因果提升。

主要 Bad Case：

- “床品”过滤掉目录中标题为“纯棉床单被套三件套”的 P1122，说明仅用任务名字符串包含判断过严，需要验证受控同义词/类目属性映射。
- “夹在床边用来照明的小灯”未召回夹式台灯，关键词档对语义表达覆盖弱。
- “擦身体而且干得快的布”无召回，关键词档未理解毛巾语义。
- “去海边下水需要穿的衣服”只覆盖部分泳衣候选，召回覆盖仍不足。

下一轮先由两位标注者复核全部正例与 Top-K 候选，裁定同义词和近邻品类；冻结 v0.1 后，新增一批未参与规则调整的 Holdout Query，再比较关键词、向量召回及槽位过滤组合。按场景、槽位、表达类型分别报告 Recall 与 Precision，并在目录覆盖缺失时单列，不把空候选混进相关性准确率。
